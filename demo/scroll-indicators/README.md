
零依赖。GNOUS 现在的滚动是「能滚但没有任何指示」：`src/main.rs` 的 `content()` 和
`src/pages/processes.rs` 的表体都只用了 `overflow_y_scroll()`，没接 `gpui-base` 的
`scrollbar`，也没自绘拇指。

## 第二版的核心约束：滚轮可以是坏的

第一版所有卡片只能滚轮滚，等于把「没有滚轮 / 滚珠坏了」的人挡在门外。第二版每个方案都必须
自己就是操作面，四条保底通道在**每一张卡**上都成立：

| 操作 | 说明 |
|------|------|
| 按住内容上下拖 | 内容跟着指针走，等于触屏拖动，不依赖任何指示器 |
| 点舞台上下边缘（各 20% 高） | 翻一屏，带平滑动画 |
| 点 / 拖右侧指示器 | 点哪跳哪，按住连续走（各方案自己的形态） |
| 键盘 ↑ ↓ PgUp PgDn Home End | 点一下卡片让它聚焦，然后按键 |

另外每条方案的专属操作：

| # | 名字 | 专属操作 |
|---|------|----------|
| 01 | 边缘渐隐 | 无（靠上面四条保底） |
| 02 | 角标百分比 | 点 `▲` `▼` 翻屏，**按住可连翻** |
| 03 | 刻度点 | 整列圆点是一条可拖定位带，点哪跳哪 |
| 04 | 迷你地图 | 点空白处跳过去；抓住视口框拖动细扫 |
| 05 | 顶部发丝 | 顶边压了 18px 高透明热区，点/拖都行 |
| 06 | 边缘光斑 | 直接抓光团上下拖 = 拖整个列表 |
| 07 | 章节刻度 | 点某根刻度跳那一节，按住轨道连续走 |
| 08 | 章节胶囊 | 点 `◀` `▶` 按节前进/后退 |
| 09 | 边界张力 | 点浮出的 `TOP` / `End` 跳到另一头 |
| 10 | LED 刻度 | 整列刻度是一条可拖定位带 |

另外两个改动，也是被「没滚轮」逼出来的：

- **02 / 06 / 08 的指示器改成「鼠标进舞台就显示」**，而不是「滚动时才出现」。否则滚轮坏了
  就永远触发不了显示，指示器等于不存在。
- **细线的命中区不再细**（05 是 18px 高、06 是 44px 宽、07/03/10 整条都能点），视觉可以
  很细，可点的东西不能细。

## 打开后的辅助

- `?pos=0.62`：让所有滚动区跳到 62%，一次看清各指示器的中段形态。
- 点卡片顶栏 = 选中，底部条记住选择（localStorage）。
- 原生滚动条全部隐藏，避免混进来干扰判断。

## 十个方向的取舍

| # | 名字 | 机制 | 最强的点 | 最大的坑 |
|---|------|------|----------|----------|
| 01 | 边缘渐隐 | 上下边缘渐变，内容溶进背景 | 零 chrome，最干净 | 完全不知道自己在哪 |
| 02 | 角标百分比 | 右下胶囊：`%` + ▲▼ 按钮 | 实现最便宜，按钮可连翻 | 看不到「还有多长」 |
| 03 | 刻度点 | 12 个等距圆点，当前点放大发光 | 像页码，定位带好抓 | 视觉上只分 12 段 |
| 04 | 迷你地图 | 内容缩略 + 视口框 | 能看出内容结构 | 要逐行映射，成本最高 |
| 05 | 顶部发丝 | 顶部 1px 线随进度填充 | 不占右侧，阅读进度感 | 和吸顶表头争位置 |
| 06 | 边缘光斑 | 右缘一团光，无轨道 | 完全无形，还是个好把手 | 只能表示「在哪」 |
| 07 | 章节刻度 | 6 根分节刻度 + 当前章节名 | 语义化，页边索引感 | 依赖内容有分节 |
| 08 | 章节胶囊 | 底部胶囊 ◀ `04 存储` 4/6 ▶ | 语义化，且是遥控器 | 看不到段内进度 |
| 09 | 边界张力 | 渐隐 + 到头呼吸红光 + TOP/END | 用触感代替位置条 | 过程无指示 |
| 10 | LED 刻度 | 26 根短横线依次点亮 | 有节奏、离散、无连续条 | 刻度密度固定 |

## 移植到 GPUI 时的成本

- 最低：02 / 05 / 09 / 10 —— 几个 `div` + 百分比。
- 中等：03 / 06 / 07 / 08 —— 需要滚动偏移（GPUI 的 `overflow_y_scroll` 不吐进度，得自己
  维护 `scroll_top` 或用 `ScrollHandle`），07/08 还要各节偏移。
- 最高：04 —— 每行都要映射成缩略线。

**这一版新增的硬要求**：无论选哪个方案，移植时都必须实现
`on_mouse_down` → `on_mouse_move` → `on_mouse_up` 的拖动改 `scroll_top`，
以及 `content()` 的键盘滚动 action。只做视觉不做操作面，等于复现第一版的问题。

选定后建议只保留一个方案 + 三条明确参数：静止多久后隐藏、右侧留多少 gutter、
可点击热区多大。
